## 这是什么

Todox 是一个**只在你电脑上运行**的待办应用。没有账号、没有云端、没有遥测，
数据就是一个 SQLite 文件，你自己可以随时打开看。

它想解决的核心问题只有一个：**记一件事不应该需要打断手上的工作**。
所以它提供三种"随手记"的方式，都支持中文自然语言：

| 方式 | 操作 | 适用场景 |
|---|---|---|
| 全局快捷键 | `Ctrl+Alt+Space` | 任何时候，唤出悬浮窗记一条 |
| 悬浮窗 | 托盘图标左键 | 顺手看一眼接下来要做什么 |
| 主窗口 | `Ctrl+Alt+N` | 需要完整视图时 |

## 下载安装

### 方式一：直接下载（推荐）

1. 打开本仓库的 [Releases](https://github.com/toweralpha/Todox/releases) 页面
2. 下载 `Todox_x.x.x_x64-setup.exe`（NSIS 安装包）或 `.msi`
3. 双击安装，装完会在开始菜单和托盘出现

> 首次运行 Windows 可能提示"未知发布者"，因为安装包没有代码签名证书
> （个人项目未购买证书）。点「更多信息」→「仍要运行」即可。

### 方式二：从源码构建

见下方 [从源码构建](#从源码构建)。

### 系统要求

- Windows 10 1809 或更高（需要 WebView2，Win11 与较新的 Win10 已内置）
- 约 50 MB 磁盘空间

## 快速上手

装上之后，**先试这三步**：

**1. 验证提醒真的会响**

按 `Ctrl+Alt+Space` 唤出悬浮窗，输入：

```
30秒后 测试提醒
```

回车。等 30 秒 —— 右下角会出现一条**停留不消失**的通知，带「打开 Todox」
和「稍后提醒」两个按钮。

> 这条通知用的是 Windows 的"提醒（reminder）"场景，它不会像普通通知那样
> 几秒后自动消失，而是等你处理。这是刻意的：错过的提醒等于没有提醒。

**2. 记一件明天要做的事**

在输入框里输入：

```
明天下午3点 交房租
```

你会看到实时预览显示它被理解成了什么。点保存后，它会出现在「今天」
（如果是今天）或「日历」里对应的那一天。

**3. 建一个每周重复的任务**

```
每周一早上9点 提交周报
```

在列表里勾选它 → 这一轮标记完成，同时**自动推进到下一个周一**。

## 功能

### 任务与时间

- **四种时间类型**：指定时刻 · 截止时间（可分级提醒）· 全天 · 重复
- **重复规则**：每天 / 每周几 / 每月某日 / 每 N 天，支持指定时刻
- **重复任务完成即推进**：勾选后自动算出下一次出现的时间，并记录每一轮
- **逾期任务不会被藏起来**：始终出现在「今天」视图顶部并标红 ——
  逾期项若被"接下来的事"过滤掉，用户就会彻底忘掉它

### 提醒

- **分级提醒**：截止型任务默认「前 1 天 / 前 1 小时 / 到点」，可在设置里增删
- **全天任务提醒钟点可配**（默认 09:00），避免半夜弹通知
- **勿扰时段**：支持跨午夜（如 23:00–07:00）
- **补发**：应用没运行时错过的提醒，下次启动会汇总成一条横幅告知
- **稍后提醒**：可设置推迟时长

### 界面

- **今天 / 收件箱 / 即将到期 / 全部** 四个列表视图
- **日历**：月视图（每格显示任务圆点）+ 选中某天的日视图
- **完成统计**：概览数字 · 每日完成柱状图 · 按任务排行
- **悬浮窗**：置顶小面板，显示最近 6 件事 + 输入框，失焦自动隐藏
- 深色 / 浅色 / 跟随系统

### 数据

- **导入导出 JSON 备份**，支持两种模式：
  - **清空并复原**：用备份完整替换当前数据
  - **仅合并**：按 ID 合并，保留当前已有的数据
- **托盘常驻**：关掉窗口不退出，提醒照常工作
- **开机自启**（可选）

## 自然语言能识别什么

中文优先，识别结果会在保存前**实时预览** —— 你能看到它是怎么被理解的，
而不是存完了才发现理解错了。

### 时间点

| 输入 | 识别为 |
|---|---|
| `14:30 开会` `下午3点 开会` | 今天 14:30 / 15:00 |
| `八点半 起床` | 今天 08:30（支持中文数字） |
| `9点钟 打卡` | 今天 09:00 |

### 日期

| 输入 | 识别为 |
|---|---|
| `明天 买牛奶` | 明天（全天） |
| `后天 交报告` | 后天（全天） |
| `下周一 例会` | 下周的周一 |
| `10月1日 国庆` | 今年 10-01（已过则明年） |
| `十五号 还款` | 本月 15 号（已过则下月） |

### 相对时长

| 输入 | 识别为 |
|---|---|
| `10秒后 提醒我` | 10 秒后（秒级，用来验证提醒很方便） |
| `30分钟后 关火` | 30 分钟后 |
| `3小时后 取快递` | 3 小时后 |
| `2天前 发生了什么` | 2 天前那一天 |

### 重复

| 输入 | 识别为 |
|---|---|
| `每天 8:00 吃药` | 每天 08:00 |
| `每周一早上9点 提交周报` | 每周一 09:00 |
| `每月1号 交房租` | 每月 1 日 |
| `每3天 浇花` | 每 3 天 |

### 时间已经过去了怎么办

说「下午3点」而现在已经 16:00 → 自动顺延到**明天下午3点**。
待办应用里没人想为已经过去的时刻建任务。

## 资源占用

实测数据（release 构建，按父子进程关系精确筛选进程树）：

| 场景 | 内存 | 目标 | 结论 |
|---|---|---|---|
| **托盘常驻**（关掉窗口） | **28–33 MB** | ≤120 MB | 达标 |
| 托盘空闲 CPU | **0 ms / 25 s** | 无轮询 | 达标 |
| 主进程 | 32.6 MB | ≤50 MB | 达标 |
| 可执行文件 | 7.0 MB | — | — |
| 窗口可见时 | 354 MB | ≤120 MB | **未达标** |

### 关于「窗口可见时 354 MB」：一个没有消除的开销

这一项**超标**，而且我没有把它藏起来。

原因是 WebView2 —— Windows 上的 Tauri 用的是 Chromium 内核，
它有 6 个子进程（GPU、渲染、网络、utility 等），合计约 354 MB。
这是 Chromium 的固有开销，不是我的代码造成的，也无法通过优化代码消除。

**我能做的是让它不常驻**：关掉窗口时销毁整个 WebView，释放 **321 MB**，
只剩托盘进程的 28–33 MB。所以真实使用中的内存曲线是：

```
打开窗口 → 354 MB      关掉窗口 → 28 MB
```

**如果你要求窗口可见时也 ≤120 MB**，那整个 WebView 方案就不成立，
需要改用 WinUI/WPF 原生重写界面 —— 那是另一个量级的工程。
我认为为了一个待办应用付出这个代价不值得，所以选择了"关窗即释放"。

## 常见问题

**通知不弹出来？**

按顺序排查：

1. **检查系统通知权限**：设置 → 系统 → 通知，确认 `Windows PowerShell`
   没有被关闭。Todox 通过 PowerShell 弹通知（原因见
   [设计决策](docs/设计决策.md#通知为什么不直接用-winrt)），
   所以这个开关会影响它。
2. **检查专注助手 / 勿扰模式**：Todox 用的是 Windows 的"提醒"场景，
   正常情况下能穿透勿扰，但系统设置里可以完全禁用。
3. **检查 Todox 自己的通知开关**：设置 → 通知，确认没有被关掉。
4. **检查勿扰时段**：设置 → 勿扰时段，确认当前时间不在其中。

**托盘图标不见了？**

Windows 会把不常用的托盘图标折叠起来。点任务栏的 `^` 展开，
把 Todox 图标拖到可见区域。

**`Ctrl+Alt+Space` 没反应？**

快捷键可能已被别的程序占用（这是常见情况，比如某些输入法、截图工具）。
启动时若注册失败会在日志里提示。可以：
- 改用托盘图标左键
- 或者关掉占用该快捷键的程序

**数据存在哪里？**

```
%APPDATA%\com.tower.todox\todox.db
```

在资源管理器地址栏粘贴 `%APPDATA%\com.tower.todox` 即可打开。
这是一个标准 SQLite 文件，可以用任何 SQLite 工具读写。
应用启动时也会把数据目录打印到标准输出。

**怎么彻底卸载？**

卸载程序不会删除你的数据（这是刻意的 —— 卸载后重装不该丢任务）。
要彻底清理，手动删掉上面那个目录即可。

**备份怎么迁移到新电脑？**

设置 → 导入导出 → 导出 JSON → 拷到新电脑 →
新电脑上安装 Todox → 导入 → 选「清空并复原」。

## 从源码构建

### 前置要求

- [Rust](https://rustup.rs/)（stable 工具链）
- [Node.js](https://nodejs.org/) 18+ 与 [pnpm](https://pnpm.io/)
- Visual Studio 生成工具（含 C++ 生成工具与 Windows SDK）

### 构建步骤

```bash
git clone https://github.com/toweralpha/Todox.git
cd Todox

pnpm install

# 开发模式（热重载）
pnpm tauri dev

# 打包出安装程序
pnpm tauri build
```

产物在 `src-tauri/target/release/bundle/`。

### 开发命令

```bash
# Rust 侧
cd src-tauri
cargo test --all-targets              # 241 个测试
cargo clippy --all-targets -- -D warnings   # 必须零警告
cargo fmt

# 前端
pnpm run check                        # svelte-check，必须 0 错 0 警
pnpm run build
```

## 已知限制

这些是我**知道且选择暂不解决**的问题，写出来而不是藏起来：

| 限制 | 原因 | 影响 |
|---|---|---|
| 窗口可见时内存 354 MB | WebView2 的 Chromium 固有开销 | 关窗后释放 321 MB |
| 通知的「稍后提醒」按钮无效 | 需要 deep-link 插件与 `on_open_url` 处理 | 点击无反应，提醒本身不受影响 |
| 导入不支持超大备份 | 需要流式解析，属架构级改动 | 超过 100 MB 会被拒绝 |
| 导入的畸形行不计数 | 需要给导入结果加字段 | 恢复时可能静默丢行 |
| 没有代码签名 | 个人项目未购买证书 | 首次运行有 SmartScreen 提示 |
| 只有中文界面 | 项目定位是中文优先 | — |
