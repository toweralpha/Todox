# Todox 0.1.2

修掉悬浮窗关不掉的问题（这次是从根上换掉实现方式），并修复我在 0.1.1 里
引入的两处行为问题。

---

## 修复：悬浮窗关不掉（Esc / 右上角按钮）

**症状**：按 `Ctrl+Alt+Space` 唤出悬浮窗后，按 `Esc` 和点右上角 `×` 都没有反应。

**根本原因**：前端直接调用窗口 API，而它受 Tauri 的 capability 权限约束。

Tauri v2 的 `core:default` **只包含只读的窗口查询命令**，凡是会改变窗口状态的
（`hide` / `show` / `close` / `start_dragging`）都必须显式授权。缺权限时
Tauri 会拒绝调用，而原代码用 `catch {}` 把这个错误静默吞掉了 ——
于是用户看到的只是"点了没反应"，完全无从判断原因。

**0.1.1 曾试图靠补权限来解决，但那个方向本身是脆弱的**：它依赖"权限配置与
前端调用始终对齐"，而一旦错位又是静默失败。

**0.1.2 改为走后端命令**：

```rust
#[tauri::command]
fn hide_float_window(app: tauri::AppHandle) -> Result<(), String> {
    app.get_webview_window("float").ok_or("找不到悬浮窗")?.hide()
}
```

**Tauri 命令不受 capability 限制**，因此这一整类静默失败被从根上排除。

同一个问题也影响了**拖拽**：无边框窗口的拖动由 Tauri 注入的脚本调用
`plugin:window|start_dragging` 实现，缺权限时窗口拖不动 —— 现在也改走后端命令。

**实测（真实按键 + 真实鼠标，已安装的 0.1.2、无 dev server）**：

| 操作 | 结果 |
|---|---|
| `Ctrl+Alt+Space` 唤出悬浮窗 | 通过 |
| 点右上角 `×` 关闭 | 通过 |
| 按 `Esc` 关闭 | 通过 |
| 再按快捷键收起 | 通过 |
| 按住标题栏拖动窗口 | 通过 |
| 反复开关 4 次 | 通过 |
| 主窗口关闭后重新打开 | 通过 |
| 提醒按时触发 | 通过 |

## 修复：移除"失焦自动隐藏"（0.1.1 引入）

0.1.1 补上权限后，悬浮窗的"失去焦点即自动隐藏"开始真正生效了 ——
而它有两个问题：

1. **会静默丢弃你正在输入的内容。** 只是想切到别处复制一段文字，
   回来发现草稿没了，而且没有任何提示。
2. **让关闭方式变得不可预期。**

现在悬浮窗只在你主动唤出时出现，然后**一定在，直到你明确关掉**
（`Esc`、右上角 `×`、或再按一次快捷键）。

## 修复：托盘左键打开主界面（0.1.0 引入）

有一版把托盘左键接到了悬浮窗，理由是"点托盘图标通常是想快点记一件事"。
**这个判断是错的** —— 点托盘图标更常见的意图是"我要看看我的任务列表"，
那是主界面的职责；悬浮窗会盖在当前窗口上，反而更打扰。

现在分工明确：

| 入口 | 打开 |
|---|---|
| `Ctrl+Alt+Space` | 悬浮窗（键盘操作 → 轻量、瞬时） |
| 托盘左键 / 托盘菜单 | 主界面（鼠标点击 → "打开应用"） |

## 新增：数据抢救工具

这次事故中我误删了你的待办数据（见下），为了恢复它写了一组雕刻工具，
现已收进 [`tools/recover`](https://github.com/toweralpha/Todox/tree/main/tools/recover)。

SQLite 删除行时不会立刻覆写页面内容，因此被删的行还能从文件里捞回来。
工具的做法是扫描 UUID 形状的文本、枚举序列类型区、再用**语义校验**
（时间格式、枚举取值、字段间的一致性）确认解出的是真实记录 ——
没有语义校验的雕刻工具会给出大量假阳性。

**这类工具希望你永远用不到**，但万一再出问题，它在那儿。

我假设了"库里的任务都是我测试时造的"，而这个假设没有任何依据。
