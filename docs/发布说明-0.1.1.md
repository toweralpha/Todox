# Todox 0.1.1

修复 0.1.0 的一个严重可用性问题，并修掉一个统计日期错位的 bug。

---

## 修复：悬浮窗关不掉

**症状**：用 `Ctrl+Alt+Space` 唤出悬浮窗后，点右上角的关闭按钮没反应、按 `Esc` 也没反应 —— 窗口只能靠再按一次快捷键或托盘菜单收起。

**原因**：悬浮窗缺少一项 Tauri 权限。

Tauri 的 `core:default` 权限集只包含**只读**的窗口查询命令，**不包含任何会改变窗口状态的命令**。而悬浮窗的关闭按钮、`Esc`、以及"失焦自动隐藏"都要调用 `window.hide()`，需要单独授权 `core:window:allow-hide`。

缺少它时 Tauri 会拒绝调用并返回：

```
window.hide not allowed.
Permissions associated with this command: core:window:allow-hide
```

而原代码把这个错误**静默吞掉**了，所以用户看到的只是"点了没反应"，完全无从判断原因。

顺带修掉同一类的第二个问题：无边框悬浮窗的拖拽区需要 `core:window:allow-start-dragging`，同样缺失，因此**之前悬浮窗也拖不动**。

**现在的行为**：

| 操作 | 0.1.0 | 0.1.1 |
|---|---|---|
| 点关闭按钮 | 无反应 | 正常隐藏 |
| 按 `Esc` | 无反应 | 正常隐藏 |
| 切到别的窗口 | 不自动隐藏 | 自动隐藏 |
| 拖动悬浮窗标题区 | 拖不动 | 可拖动 |

> 如果升级后仍有关不掉的情况，那一定是别的原因 —— 现在失败会写 `console.error`
> 并明确指出缺少哪项权限，不会再无声无息。

## 修复：统计的"今天"错位一天

**症状**：凌晨完成的待办，在统计里被算到前一天 —— 「今天完成数」显示 0，而昨天那一栏多出一条。

**原因**：统计查询用了 SQLite 的 `date(completed_at)` 和 `date('now')` 来比较日期。

Todox 存储的时间戳是**带本地时区偏移**的（`2026-10-01T00:30:00+08:00`，这是刻意的设计，为了"今天"永远等于用户看到的那一天）。但 SQLite 的 `date()` 会把它**规范化成 UTC**，于是 UTC+8 用户的凌晨记录变成了前一天；而 `'now'` 在 SQLite 里**也是 UTC**，不是本地时间。两者叠加，日期就错开了一天。

原来的代码注释还写着「`date()` 能正确取出其日期部分」「`'now'` 是 SQLite 的本地时间」—— **这两句都是错的**，正是它们让这个 bug 一直没被发现。

**修复**：我们存储格式的前 10 个字符**就是本地日期**，直接用 `substr(completed_at, 1, 10)` 取出，并把起始日期从 Rust 侧按本地时间算好后作为参数传入 —— 不做任何 UTC 往返。

新增两个**确定性**回归测试。它们刻意各插入「昨天 23:59:59」与「今天 00:00:01」两条边界记录：只测一个边界时，在某些时区或一天中的某些时段测不出问题，两条都测才能保证任何情况下都能区分出正确与错误的实现。（这两个测试都经过验证：在修复前的代码上确实失败。）

## 升级方式

直接运行新的安装包覆盖安装即可，**数据不会丢失**（任务存在
`%APPDATA%\com.tower.todox\todox.db`，与程序本体分离）。

卸载旧版也不会删除数据，所以你也可以先卸载再装。
